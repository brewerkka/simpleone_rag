# SimpleOne RAG - Система семантического поиска по документации

RAG (Retrieval-Augmented Generation) система для семантического поиска по документации SimpleOne API. Позволяет задавать вопросы на естественном языке и получать релевантные ответы на основе документации.

## 🚀 Возможности

- **Семантический поиск** - поиск по смыслу, а не по ключевым словам
- **Интеллектуальное разбиение текста** - использование кластеризации для создания семантически связанных чанков
- **Векторное хранилище** - использование FAISS для быстрого поиска похожих документов
- **LLM интеграция** - использование Groq API для генерации ответов
- **Веб-интерфейс** - удобный Streamlit интерфейс для взаимодействия

## 📋 Требования

- Python 3.8+
- Groq API ключ (получите на [groq.com](https://groq.com))

## 🔧 Установка

1. **Клонируйте репозиторий** (если используете git):
```bash
git clone <repository-url>
cd simpleone_rag
```

2. **Установите зависимости**:
```bash
pip install -r requirements.txt
```

3. **Настройте переменные окружения**:
Создайте файл `.env` в корне проекта:
```bash
GROQ_API_KEY=your_groq_api_key_here
```

4. **Подготовьте данные**:
Убедитесь, что исходные JSON файлы находятся в соответствующих директориях:
- `data_simpleone/client_side_api.json`
- `test/ru_server_side_api.json`
- `test/ru_widgets.json`

## 📖 Использование

### Шаг 1: Создание чанков из исходных данных

Обработайте исходные JSON файлы и создайте чанки:

```bash
make chunk
# или
python3 chunks/chunker.py
```

Это создаст файлы:
- `chunks/client_chunks.json`
- `chunks/server_chunks.json`
- `chunks/widgets_chunks.json`

### Шаг 2: Построение векторного индекса

Создайте векторный индекс из чанков:

```bash
make index
# или
python -m scripts.build_index
```

Индекс будет сохранен в `vectorstore/faiss_index/`.

### Шаг 3: Запуск веб-интерфейса

Запустите Streamlit приложение:

```bash
make ui
# или
streamlit run streamlit_app.py
```

Приложение откроется в браузере по адресу `http://localhost:8501`.

## ⚙️ Конфигурация

Все настройки находятся в файле `config.yaml`:

```yaml
# Пути к исходным данным для обработки
source_data:
  client_side_api: data_simpleone/client_side_api.json
  server_side_api: test/ru_server_side_api.json
  widgets_side_api: test/ru_widgets.json

# Пути к обработанным чанкам
paths:
  - chunks/client_chunks.json
  - chunks/server_chunks.json
  - chunks/widgets_chunks.json

# Настройки векторного хранилища
vectorstore:
  path: vectorstore/faiss_index
  model: all-MiniLM-L6-v2  # Модель для эмбеддингов

# Настройки LLM
llm:
  model: llama-3.1-8b-instant  # Модель для генерации ответов
  api_key_env: GROQ_API_KEY

# Настройки поиска
retrieval:
  k: 5  # Количество релевантных документов для извлечения

# Настройки чанкинга
chunking:
  target_sent_count: 5
  distance_threshold: 1.0
  min_words: 10
  max_words: 150
```

## 🔍 Как это работает

1. **Чанкинг**: Исходные документы разбиваются на семантически связанные чанки с использованием кластеризации на основе эмбеддингов предложений.

2. **Индексация**: Чанки преобразуются в векторные представления (эмбеддинги) и индексируются в FAISS для быстрого поиска.

3. **Поиск**: При запросе пользователя:
   - Запрос преобразуется в эмбеддинг
   - Находятся k наиболее похожих чанков
   - Эти чанки передаются в LLM вместе с запросом
   - LLM генерирует ответ на основе найденной информации

Приложение создает файл `rag_app.log` с логами всех запросов и ответов. Это полезно для отладки и анализа использования системы.

## ⚠️ Устранение неполадок

### Ошибка: "Переменная окружения GROQ_API_KEY не установлена"
Убедитесь, что файл `.env` существует и содержит правильный API ключ.

### Ошибка: "FAISS-индекс не найден"
Выполните `make index` для создания векторного индекса.

### Ошибка: "Файл не найден" при создании чанков
Проверьте, что исходные JSON файлы находятся в правильных директориях согласно `config.yaml`.

## 🔒 Безопасность

- Никогда не коммитьте файл `.env` с API ключами в репозиторий
- Файл `.env` уже должен быть в `.gitignore`
- Используйте переменные окружения для хранения секретных данных
